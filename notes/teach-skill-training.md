## 一、这个 skill 是什么

/teach 是一个 **stateful（有状态）教学 skill**，把 AI agent 变成私人老师，让你用它学任何东西。装进 coding agent（Claude Code / Codex 等）后，在当前目录建起一整套教学工作区，跨会话记住你学到哪、卡在哪。

**与普通 chat 的本质区别**：普通对话每次从零开始，/teach 把每节课、每条进度、每个术语都存进文件系统，下次打开 agent 它记得一切。

**视频中的演示案例**：Matt 用它从零学会了还原魔方。

---

## 二、核心设计取舍：Stateful vs Stateless

这是整个 skill 最关键的设计决策，也是视频的第一个看点。

| | /teach（stateful） | /grill-me（stateless） |
|---|---|---|
| 状态存储 | 文件系统（当前目录） | 无，每次会话独立 |
| 适用场景 | 长期学习（多会话） | 一次性决策/计划对齐 |
| 记忆方式 | learning-records 记录进度 | 会话内上下文 |
| 设计原因 | 学习需要跟踪进度、计算最近发展区 | 追问不需要历史，每次从零开始反而更彻底 |

**为什么 /teach 必须是 stateful**：学习是渐进过程，agent 需要根据你已掌握的内容判断下一课教什么（最近发展区），没有状态就做不到。

**为什么 /grill-me 必须是 stateless**：追问的目的是暴露假设、理清决策树，历史状态反而会带来偏见，每次从零开始追问更彻底。

## 三、教学工作区完整结构

/teach 在当前目录创建以下文件和目录：

```
你的工作目录/
├── MISSION.md              # 学习目标（为什么学）
├── RESOURCES.md            # 高可信参考资料清单
├── NOTES.md                # agent 的记事本（用户偏好、工作笔记）
├── GLOSSARY.md             # 术语表（自动生成，所有课程遵守）
├── reference/              # 参考文档（HTML，可打印）
│   └── *.html              #   速查表、算法、语法、术语等
├── lessons/                # 课程目录（HTML，核心产出）
│   ├── 0001-xxx.html       #   编号递增，每课一个文件
│   ├── 0002-xxx.html
│   └── ...
├── learning-records/       # 学习记录（Markdown）
│   ├── 0001-xxx.md         #   编号递增
│   └── ...
└── assets/                 # 可复用组件（样式表、测验部件等）
    └── ...
```

### 3.1 MISSION.md — 学习目标

**作用**：记录用户为什么想学这个主题，是所有教学决策的锚点。教什么、用什么资源、设计什么练习，都要回溯到这个文件。

**格式模板**：

```markdown
# Mission: {主题}

## Why
{1-3 句话。用户追求的具体现实世界目标。学会这个技能后生活或工作会发生什么变化？
避免"为了理解 X"这种抽象表述——要挖出底层结果。}

## Success looks like
- {用户将能做的具体可观察的事情}
- {另一件具体的事}
- {…}

## Constraints
- {时间、预算、已有安排、学习偏好等限制条件}

## Out of scope
- {用户明确不想现在碰的相关主题——保护最近发展区}
```

**规则**：
- 一个工作区一个 mission。想学两个不相关的东西 = 两个工作区
- 具体优于抽象。"10 月跑完半马"好过"变健康"，"给团队交付一个 Rust CLI"好过"学 Rust"
- 用户说不清 why 就先访谈再写。差的 mission 比没有 mission 更糟
- 现实变化时修订。目标变了就更新文件，别让过时的 mission 继续指挥后续课程
- 保持简短。超过一屏就从指南针变成了计划书

### 3.2 RESOURCES.md — 参考资料清单

**作用**：策展可信来源。课程中的知识应从这里提取，而不是 agent 的参数化猜测。智慧来自这里列出的社区。

**格式模板**：

```markdown
# {主题} Resources

## Knowledge
- [书名: 《书名》— 作者](链接)
  内容简介。Use for: 什么时候用这个资源。
- [文章: "标题" — 作者 (来源)](链接)
  内容简介。Use for: 什么时候用。

## Wisdom (Communities)
- [r/xxx](链接)
  社区特点。Use for: 什么时候去这里。
- Local: 本地资源
  Use for: 什么时候去。
```

**规则**：
- 只收高可信来源。优先原始文献、公认专家、同行评审、强管理社区。营销包装成教育的一律不收
- 每条必加注释。裸链接三个月后就没用。加一行：覆盖什么、什么时候用
- 按 Knowledge / Wisdom 分组。对应 SKILL.md 的哲学。一个资源可以只在一组
- 明确标出空白。如果 mission 需要的领域没有好资源，写 `## Gaps` 章节列出缺什么，驱动后续搜索
- 无情修剪。错的、浅的、偏离 mission 的资源删掉，不要埋没。五个锐利的来源好过三十个平庸的
- 记录社区偏好。用户不想加入社区就记在这里，避免后续会话重复提议

### 3.3 lessons/*.html — 课程（核心产出）

**课程是 /teach 的主要产出**——知识和技能通过课程传递给用户。每节课是一个自包含 HTML 文件，保存在 `./lessons/`，命名为 `0001-<dash-case-name>.html`，编号递增。

**设计原则**：

1. **美观**：排版干净易读，用户会回来复习。想想 Tufte
2. **简短**：学习者的工做记忆很小，必须控制在内。但每节课给用户一个可积累的 tangible win
3. **直接绑定 mission**：每节课都要能回答"这和用户的目标有什么关系"
4. **落在最近发展区**：难度精准控制在"被挑战但不吓退"的区间
5. **互相链接**：通过 HTML 锚点链接到其他课程和参考文档
6. **推荐主源**：每节课推荐一个最高质量、最可信的资源让用户去读/看
7. **提醒提问**：每节课提醒用户可以向 agent 提问——agent 是老师，可以解答任何不清楚的地方

**为什么用 HTML 而不是 Markdown**：HTML 支持交互（测验、模拟器）、图解、测验部件，Markdown 做不到。

**打开方式**：如果可能，agent 应运行 CLI 命令直接为用户打开课程文件。

### 3.4 learning-records/*.md — 学习记录

**作用**：相当于软件开发中的 ADR（架构决策记录）。捕捉非显而易见的课程、关键洞察、用户声明的先验知识，用于计算最近发展区。

**格式极简**：

```markdown
# {学到的东西的简短标题}

{1-3 句话：学到了什么（或建立了什么先验知识），以及为什么对后续课程重要。}
```

就这么简单。学习记录可以只有一段。价值在于记录"这已经知道了"以及"它改变了接下来教什么"——而不是填满各个章节。

**可选章节**（只在真正有价值时才加）：
- Status frontmatter（active | superseded by LR-NNNN）：早期理解被纠正替换时用
- Evidence：用户如何证明了理解（答对了问题、完成了练习、引用了先前经验）
- Implications：这对后续课程解锁了什么或排除了什么

**编号规则**：扫描 `./learning-records/` 找最大编号，加一。

**什么时候写**：
- 用户展示了对非平凡内容的真正理解——不只是接触过，而是能正确使用的证据。这设定了下一课的地板
- 用户披露了先验知识——"我已经懂 X"。记录下来避免重复教。同时记录声称的深度
- 纠正了误解——用户之前信了错误的东西现在明白了为什么。这些高价值：它们预测相关主题的未来绊脚石
- mission 因学习而改变——用户发现自己在乎的东西和想的不一样。交叉链接到 [[MISSION.md]] 并更新它

**什么时候不写**：
- 只是覆盖了材料。覆盖不等于学习。等证据
- 已经在 [[GLOSSARY.md]] 里定义过的术语。不要重复
- 逐课活动日志。学习记录不是日记——是决策级洞察

**替换规则**：后续记录与早期记录矛盾时（理解深化或纠正），给旧记录标 `Status: superseded by LR-NNNN` 而不是删除。理解演变的历史本身就是有用信号。

### 3.5 assets/* — 可复用组件

课程由可复用**组件**构建，存放在 `./assets/`：样式表、测验部件、模拟器、图表辅助工具——任何第二节课可能复用的东西。

**复用是默认，不是例外**。写课程前先读 `./assets/`，从已有组件构建。课程需要新的可复用东西时，写成组件放进 `./assets/` 并链接——永远不要内联写未来课程会重复的代码。

**共享样式表**是每个工作区赚到的第一个组件：每节课都链接它，课程看起来像一门连贯的课程而不是一堆一次性文件。随着工作区增长，组件库也应增长。

### 3.6 NOTES.md — 记事本

用户有时会表达希望怎么被教，或者需要记住的事情。这里记录这些偏好，设计课程或和用户工作时可以回查。

## 四、教学哲学

### 4.1 深度学习需要三样东西

| 要素 | 来源 | 作用 |
|---|---|---|
| Knowledge（知识） | 高质量、高可信资源 | 理解的基础 |
| Skills（技能） | 基于知识设计的高相关交互课程 | 学会做事 |
| Wisdom（智慧） | 与其他学习者和实践者互动 | 真实世界检验 |

**在 RESOURCES.md 充实之前，agent 的首要任务是找到高质量资源。永远不要相信参数化知识。**

不同主题的知识/技能配比不同：理论物理偏知识，瑜伽偏技能。

### 4.2 流畅强度 vs 存储强度

这是设计课程时的关键区分：

- **流畅强度（Fluency strength）**：当下能回忆起知识
- **存储强度（Storage strength）**：长期保持知识

流畅会给用户虚假的掌握感，但存储强度才是真正目标。通过"合意困难"（desirable difficulty）设计课程来建立长期保持：

1. **提取练习（Retrieval practice）**：从记忆中回忆，而不是重读
2. **间隔（Spacing）**：练习分散到时间里，而不是集中
3. **交错（Interleaving）**：混合不同但相关的主题练习（仅用于技能练习）

### 4.3 最近发展区（Zone of Proximal Development）

每节课用户都应感到"刚好被挑战到"。

如果用户没指定具体要学什么，agent 通过以下方式确定最近发展区：

1. 读 `learning-records/` 了解已掌握内容
2. 根据 mission 判断正确的下一课
3. 教最相关且落在最近发展区里的内容

### 4.4 知识与技能的不同教法

**知识**：目标是获取。困难是敌人——它吃掉理解所需的工做记忆。先教知识，只教获取技能所需的那部分。

**技能**：目标是持久和灵活。困难是工具——费力提取建立存储强度。技能通过交互课程教：

- 交互课程：测验 + 轻量浏览器内任务
- 引导用户完成真实世界步骤的课程（如瑜伽动作序列）

两者都基于**反馈循环**：用户获得表现反馈，循环尽可能紧——即时反馈，理想情况是自动反馈。

**测验设计细节**：每个选项的单词数完全相同（字符数也尽可能相同）。不要通过格式给用户任何答案线索。

### 4.5 获取智慧

智慧来自真实世界互动——在学习环境之外检验技能。

当用户的问题看起来需要智慧时，默认姿态是尝试回答——但最终委派给**社区**。

社区是用户可以在真实世界检验技能的地方（线上或线下）：论坛、subreddit、真实课程（预算允许）、本地兴趣小组。

agent 应尝试找到高声誉社区推荐给用户。如果用户明确表示不想加入社区，尊重这个偏好。

## 五、安装与运行

### 安装

**方式一：Claude Code 插件（推荐，自动更新）**

```bash
claude plugins install mattpocock-skills
```

或在会话内：

```
/plugin install mattpocock-skills
```

**方式二：skills.sh（可复制编辑）**

```bash
npx skills@latest add mattpocock/skills
```

选择要安装的 skill（确保包含 `setup-matt-pocock-skills`），以及装到哪些 coding agent。

**方式三：手动**

```bash
git clone https://github.com/mattpocock/skills.git
```

### 首次配置

在 agent 中运行一次（每个仓库一次）：

```
/setup-matt-pocock-skills
```

它会问你：用哪个 issue tracker（GitHub / Linear / 本地文件）、triage 标签、文档保存位置。

### 开始学习

进入一个空目录，运行：

```
/teach 我想学魔方还原
```

agent 会：
1. 先问你为什么想学（建立 MISSION.md）
2. 搜索高质量资源（建立 RESOURCES.md）
3. 生成第一节 HTML 课程（lessons/0001-xxx.html）
4. 随着学习推进，自动记录 learning-records、积累 reference、扩展 assets

### 跨会话续学

下次打开 agent，告诉它：

```
继续学魔方
```

agent 会读 learning-records 判断你学到哪、卡在哪，诊断后定做下一课。

## 六、工程视角：用 /teach 做新人 onboarding

视频中提到的一个延伸用法：把新人 onboard 到一个代码库。

/teach 的工作区结构天然适合这个场景：
- MISSION.md = 新人要能达到什么状态
- RESOURCES.md = 代码库文档、架构决策记录、关键模块说明
- lessons/ = 按依赖顺序的学习路径
- learning-records/ = 新人已掌握的模块
- reference/ = 速查表（常用命令、代码规范、API 摘要）
